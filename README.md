# AIModelLearning

计算机本科阶段长期维护的 AI 学习总仓库，创建于 **2026 年 8 月**。

| 项目 | 说明 |
|---|---|
| 仓库定位 | 1 个长期维护的学习总仓库 |
| 主要用途 | Python / NumPy / PyTorch / Deep Learning / 算法 / 学习笔记 |
| 公开策略 | 可以公开；保持目录、代码和学习轨迹清晰即可 |
| 新建触发条件 | 日常课程练习和小实验不拆仓库；形成完整独立项目后再新建仓库 |

## 仓库用途

本仓库统一保存本科阶段 AI 学习过程中的课程示例、课后练习、独立重写代码、小型实验、阶段验收、错题记录和学习笔记。

它的目标是形成一条能够持续复习、运行和展示的学习轨迹。这个仓库将长期维护，小练习不拆分成大量独立仓库，也不为了增加仓库数量而提前创建空项目。

## 学习范围

### 1. Python

- 变量、数据类型、判断和循环；
- 字符串、列表、元组、集合和字典；
- 函数、文件读写、异常、模块和包；
- 类、对象、`self`、`__init__` 和基础类型注解。

### 2. NumPy

- `ndarray`、形状、索引和切片；
- 广播、向量化运算和统计操作；
- 矩阵运算以及配套的线性代数练习。

### 3. PyTorch

- Tensor 与自动求导；
- Dataset、DataLoader 和数据预处理；
- `nn.Module`、损失函数和优化器；
- 训练、验证、保存与加载模型的完整流程。

### 4. Deep Learning

- 线性回归、逻辑回归和多层感知机；
- 过拟合、正则化、归一化和优化；
- CNN 等深度学习基础模型与训练实验。

### 5. 算法与计算机基础

- 数组、链表、栈、队列、哈希表、树和图；
- 排序、查找、递归和动态规划；
- 操作系统、计算机网络和数据库课程的复习笔记。

### 6. 学习笔记

- 课程重点、代码解释和易错点；
- 阶段总结与验收结果；
- 与当前学习阶段直接相关的阅读记录。

## 日常使用方式

1. 观看少量课程并手动敲写示例；
2. 关掉视频，独立重写核心代码；
3. 完成练习并运行验证；
4. 在对应目录记录错误、结论或阶段总结；
5. 完成一个明确的小目标后提交一次 Git 记录。

建议的提交信息：

- `learn:` 完成一个知识点的学习和练习；
- `feat:` 新增一个可运行的小功能；
- `fix:` 修复代码错误；
- `docs:` 更新笔记或说明；
- `refactor:` 调整代码结构但不改变功能。

示例：

```powershell
git add .
git commit -m "learn: complete Python list and dict exercises"
```

一次提交只对应一个清晰的学习目标。

## 仓库边界

以下内容继续放在本仓库，不单独建立仓库：

- 单个知识点练习；
- 课程跟练代码；
- 小型 Notebook 实验；
- 临时验证代码；
- 尚不能独立运行或展示的半成品。

只有基本满足以下条件，才拆成独立仓库：

- 有明确、独立的项目目标；
- 能够独立安装和运行；
- 有完整 README、目录结构和运行说明；
- 有可展示的结果、实验记录或测试；
- 预计会持续迭代，而不是一次性小练习。

未来可能拆分的独立仓库：

| 仓库 | 创建时机 |
|---|---|
| `transformer-from-scratch` | 开始完整手写并验证 Transformer 时 |
| `minigpt` | 开始构建可训练、可生成的 MiniGPT 时 |
| `minirag` | 开始构建完整 RAG 系统时 |
| `paper-reproduction-xxx` | 确定第一篇正式复现论文后 |
| `research-project-xxx` | 获得正式科研课题后 |

仓库数量可以按照真实项目增减，但不要为了数量提前创建空仓库。

## 公开展示原则

本仓库可以公开，用于展示持续学习过程。公开前应确保：

- 不包含密码、API Key、个人隐私或受限制数据；
- 不上传虚拟环境、缓存、数据集、模型权重和临时输出；
- 保留的代码可以运行，文件名称和目录用途清楚；
- 重要阶段有简短说明和验收结果；
- 定期清理重复、无意义或无法说明用途的文件。

申请实验室或实习时，本仓库用于证明基础积累和持续学习能力；真正的展示重点放在后续独立项目、论文复现和科研仓库上。
